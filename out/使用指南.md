# e2e 使用指南

> 生成时间: 2026-10-11
> 分析基线: monorepo main 分支 @ 449fa936（e2e 0.19.0）
> 官方文档: https://e2e.tester.army/docs

## 1. 项目简介

[e2e](https://github.com/tester-army/e2e) 是 TesterArmy 开源的 **agentic 端到端测试框架**（Apache-2.0），用于 Web 与移动应用。用自然语言描述目标，由 agent 驱动应用完成它；同一条测试里还能用 locator 和断言做确定性校验。agent 步骤通过后续断言验证后，其动作会被记录，下次运行直接**回放而无需调用模型**；不含 agent 步骤的测试完全不需要模型。

```ts
// tests/checkout.e2e.ts
import { test, expect } from 'e2e';

test('a member upgrades to Pro', async ({ app, agent, screen }) => {
  await app.open('/settings/billing');

  await agent.act('upgrade the workspace to the Pro plan');        // 目标（自然语言）
  await agent.assert('the invoice preview shows a prorated amount'); // 语义断言

  await expect(screen.getByRole('status')).toContainText('Pro');   // 确定性断言
});
```

## 2. 快速开始

### 2.1 环境要求

| 要求 | 版本/说明 |
|------|-----------|
| Node.js | `^22.22.3 \|\| >=24.8.0`（推荐 24.8+） |
| Web 测试 | 无额外要求，Playwright 浏览器在首次运行时自动下载（Chromium/Firefox/WebKit） |
| iOS 测试 | macOS + Xcode（含 iOS simulator runtime） |
| Android 测试 | Android SDK + 模拟器（任意操作系统） |
| Windows | **官方建议在 WSL 内运行**（docs/quickstart.mdx 明确说明） |
| 模型 | 订阅（ChatGPT/Copilot/OpenCode Console/SuperGrok）、API key 或本地模型，三选一；纯 locator 测试可完全不配模型 |

### 2.2 初始化项目

```bash
# npm
npx e2e init [directory]
# pnpm
pnpm dlx e2e init
# bun
bunx e2e init
```

向导会询问引擎（**Web (Playwright)** 或 **Mobile (iOS/Android)**）与模型来源（订阅 / API key / None），然后写入：

| 文件 | 内容 |
|------|------|
| `e2e.config.ts` | 引擎 target 与模型配置 |
| `tests/example.e2e.ts` | 示例测试（不调用模型即可跑通） |
| `.agents/skills/e2e/`、`.claude/skills/e2e/` | 供编码代理阅读的 e2e skill |
| `.mcp.json`、`.cursor/mcp.json` | 注册 `e2e mcp` 服务器 |
| `package.json` | 补齐依赖与 `test:e2e` 脚本 |

非交互场景用 `npx e2e init --yes`（默认 Web 引擎 + Vercel AI Gateway）。

### 2.3 运行第一个测试

```bash
npx e2e run                # 或 pnpm exec e2e run / bunx e2e run
npx e2e run --headed       # 可视化浏览器窗口
npx e2e run tests/signup.e2e.ts:12   # 只跑第 12 行的测试
npx e2e run --grep checkout          # 按标题过滤
npx e2e run --target web             # 只跑一个 target
```

示例 Web 配置与测试（使用 Vercel AI Gateway）：

```ts title="e2e.config.ts"
import type { E2EConfig } from 'e2e';
import { web } from '@e2e-dev/web';
import { gateway } from 'ai';

export default {
  agents: { default: { model: gateway('openai/gpt-6-luna-fast') } },
  targets: [{ engine: web(), app: { url: 'http://localhost:3000' } }],
} satisfies E2EConfig;
```

```ts title="tests/example.e2e.ts"
import { test } from '@e2e-dev/web';
import { expect } from 'e2e';

test('app opens', async ({ app, browser }) => {
  await app.open('/');
  await expect(browser.locator('body')).toBeVisible();
});
```

移动端配置（iOS 打开系统设置；Android 为 `platform: 'android'` + `bundleId`）：

```ts title="e2e.config.ts"
import { mobile } from '@e2e-dev/mobile';

export default {
  agents: { default: { model: gateway('openai/gpt-6-luna-fast') } },
  targets: [{ name: 'ios', engine: mobile({ platform: 'ios' }), app: { bundleId: 'Settings' } }],
  workers: 1,
} satisfies E2EConfig;
```

移动端环境预检：`npx agent-device doctor`。

### 2.4 配置模型

**订阅方式**（`npx e2e login`）：

| 订阅计划 | 命令 |
|----------|------|
| ChatGPT Plus / Pro | `npx e2e login openai` |
| GitHub Copilot | `npx e2e login github-copilot`（可用 `--from-gh` 复用 GitHub CLI 登录） |
| OpenCode Console（Zen / Go） | `npx e2e login opencode-console` |
| SuperGrok / X Premium+ | `npx e2e login spacexai` |
| Claude Max / Team | 用计划附带的 API credits 换 API key |

**API key 方式**：安装对应 provider 包（`@ai-sdk/anthropic`、`@ai-sdk/google`、`@ai-sdk/openai`、`@ai-sdk/openai-compatible`、`@ai-sdk/xai`、`ai` 均为 e2e 的可选 peer），设置其环境变量，在 `e2e.config.ts` 里用 `agent` 构造模型。向导原生支持 Vercel AI Gateway、OpenRouter 和 OpenAI-compatible 端点。

**本地模型**：任何 OpenAI-compatible 端点（Ollama、LM Studio 等）都可通过 `@ai-sdk/openai-compatible` 接入，详见官方 Models 页。

### 2.5 添加 agent 步骤

```ts
import { test, expect, unique } from '@e2e-dev/web';  // mobile 则 from '@e2e-dev/mobile'

test('a visitor signs up for a trial', async ({ app, agent, screen }) => {
  await app.open('/');

  // params 填充目标里的占位符；每次变化的值用 unique() 包裹以便缓存回放
  await agent.act('sign up for a free trial as {name} with email {email}', {
    params: { name: 'Ada Lovelace', email: unique('ada@example.test') },
  });

  await agent.assert('the welcome screen greets Ada by name'); // 模型判定屏幕
  await expect(screen.getByRole('status')).toContainText('trial'); // 精确断言
});
```

## 3. 测试编写模型

### 3.1 三类步骤

| 步骤 | API | 是否调用模型 |
|------|-----|--------------|
| 目标 Goal | `agent.act` | 默认会；命中回放缓存则不会 |
| 断言 Assertion | `agent.assert` / `agent.waitFor` / `agent.extract` | 会（自定义 executor 可免） |
| 定位器 Locator | `screen.*` 与 `expect` | 否 |

要点：

- 每个 `agent.act` 只写**一个目标**，目标顺序由你控制；用屏幕上实际出现的词语。
- 每个 agent 步骤后用 `expect` 验证结果 —— **回放缓存只记录被后续检查通过的目标**。
- `agent.assert` 立即判定；证据不足报 `ASSERTION_INCONCLUSIVE`，假命题报 `ASSERTION_FAILED`。
- `agent.waitFor` 等待条件成立，仅在屏幕变化时调用模型。
- `agent.extract` 按 Standard Schema（如 Zod）从屏幕读取结构化数据。
- 视觉判定加 `{ vision: true }`（截图+文本）或 `{ vision: 'only' }`（仅截图）；填过密码后本次 attempt 不再发送截图。
- 所有 agent / screen 调用必须 `await`，否则测试以 `STEP_NOT_AWAITED` 失败。

### 3.2 定位器（无模型、确定性）

```ts
// 优先级：role+name > label > testId
await screen.getByRole('button', 'Sign in').tap();
await screen.getByLabel('Email').fill('ada@example.test');

// 过滤与作用域
const row = screen.getByRole('listitem').filter({ hasText: 'Design review' });
await row.getByRole('button', 'Archive').tap();

// 手势与坐标
await screen.swipe({ direction: 'up' });
await screen.getByRole('image', 'Seat map').tap({ position: { x: 120, y: 48 } });

// 断言自动重试直至通过或超时
await expect(screen.getByRole('status')).toHaveText('2 remaining');
```

查询命中多个节点时动作失败，需用 `.filter()` / `.first()` / `.nth()` 收敛到唯一节点。

### 3.3 组织测试

```ts
import { beforeEach, describe, test } from 'e2e';

describe('billing', { tags: ['billing'] }, () => {
  beforeEach(async ({ app }) => { await app.open('/billing'); });

  test('upgrades', { retries: 2, timeout: 60_000 }, async ({ agent }) => {
    await agent.act('upgrade to Pro');
  });
});
```

- 每个测试独占一个 attempt（一次全新会话）；数据准备放 fixture / hook（`test.extend`）。
- 跨测试流程用 `{ serial: true }` 串行组，同 worker 顺序执行、共同重试。
- `test.skip(condition, reason)` 条件跳过。
- 需要 `browser` / `device` fixture 类型时，`test` 从 `@e2e-dev/web` / `@e2e-dev/mobile` 导入。

## 4. 配置说明（e2e.config.ts）

TypeScript 原生支持（内部用 oxc 转译加载）。顶层主要配置项：

| 配置项 | 说明 |
|--------|------|
| `agents` | 每个命名 agent 的 `model`、`judge`（判定模型）、`executor`（自定义步骤执行器，如 decision）、`context`（全局上下文）、`maxInputTokens`、`maxModelCalls`、超时等 |
| `targets` | 必填。每项 `engine: web() / mobile() / 自定义引擎` + `name` + `app` 配置 |
| `app.url` | Web：`app.open()` 的基地址；相对导航据此解析。loopback 主机才允许明文 HTTP |
| `app.bundleId` / `app.appPath` | Mobile：已安装应用 / 待安装构建（.app 或 .apk） |
| `app.identity` | 回放缓存与会话的稳定标识，默认取 URL origin+base path / bundleId / appPath；预览 URL 场景应显式设置 |
| `app.command` / `readyUrl` | 测试前自动启动的进程（dev server、Metro），退出时一并停止；`{port}` 占位符支持随机端口 |
| `workers` / `retries` | 并行 worker 数与重试次数（CI 默认 workers=1、retries=1） |
| `reporters` | `list` / `json` / `junit` / `markdown` 内置，加 reporter 对象（如 `github()`） |
| `output` | 结果目录，默认 `.e2e/`：`report.json`、`results/`、`sessions/`、`ai-trace.json` 等 |
| `artifacts` / `trace` / `video` | 产物录制模式：`off` / `on` / `retain-on-failure` / `on-first-retry` / `on-all-retries` |
| `cache` | 回放缓存模式：`read-write`（默认）/ `read-only` / `off`；`strict` 子项让过期录制直接失败 |
| `credentials` / `secrets` | 登录复用与密钥声明；**模型永远看不到 secret 的值**（详见安全模型） |
| `failOnSkippedFailure` | 跳过的测试是否算失败 |

环境变量解析顺序、CI 检测（`CI=1` 时 cache 未配置则只读、`test.only` 报 `ONLY_IN_CI`）等细节见官方 reference/config 页。

## 5. CLI 命令总览

```bash
npx e2e init [directory]        # 初始化项目（引擎/模型向导）
npx e2e login [provider]        # 订阅登录（openai | github-copilot | opencode-console | spacexai）
npx e2e logout [provider]
npx e2e models [provider]       # 列出可用模型
npx e2e guide [topic]           # 打印内置给编码代理的 skill 文档
npx e2e mcp                     # 启动 MCP 服务器（供 Claude Code / Cursor 等驱动真实运行）
npx e2e run [files...] [flags]  # 运行测试
npx e2e explore [goal]          # 用 agent 探索应用并输出发现报告
npx e2e telemetry [status|enable|disable]
```

`e2e run` 常用 flag：

| Flag | 说明 |
|------|------|
| `--headed` | 有界面运行（引擎支持时） |
| `--grep` / `--grep-invert` | 按测试标题正则过滤 |
| `--target` / `--tag` / `--exclude-tag` | 按 target / 标签选择 |
| `--last-failed` | 只重跑上次未通过的测试（读 `report.json`） |
| `--shard <i/total>` | CI 分片 |
| `--workers` / `--retries` / `--repeat-each` / `--max-failures` | 运行控制 |
| `--no-cache` | 本次运行禁用回放缓存（强制走模型） |
| `--strict-cache` | 录制过期直接报 `REPLAY_STALE`，不回退到模型；绝不写缓存 |
| `-u, --update-snapshots` | 更新 `toHaveScreenshot` 基线截图 |
| `--trace [mode]` / `--video [mode]` | 按本次运行覆盖 trace 页 / 视频录制 |
| `--reporter <ids>` | 覆盖内置 reporter（`list`/`json`/`junit`/`markdown`） |
| `--output <dir>` | 结果目录（默认 `.e2e`） |
| `--debug` | stderr 输出分阶段耗时表 + agent 步骤表（含 token 与成本） |
| `--ai-trace` | 每次模型调用记录到 `ai-trace.json`，用 unbox-ai 分析 |
| `--pass-with-no-tests` | 无测试时退出码 0 |

## 6. 生态包按需安装

| 包 | 用途 | 接入方式 |
|----|------|----------|
| `@e2e-dev/web` | Web 引擎（Playwright，Chromium/Firefox/WebKit） | `engine: web()`；贡献 `browser` fixture |
| `@e2e-dev/mobile` | 移动引擎（agent-device，iOS/Android） | `engine: mobile({ platform })`；贡献 `device` fixture；`@e2e-dev/mobile/tools` 提供 `open_app`/`swipe`/`alert` 工具 |
| `@e2e-dev/decision` | 决策模型执行器（概率分布选择动作，token 消耗更低） | `agents.default.executor = decisionExecutor({ model, ... })` |
| `@e2e-dev/kernel` | Kernel 云托管 Chromium（CDP 接入，支持 stealth） | `web({ browser: kernel() })`，需 `KERNEL_API_KEY` |
| `@e2e-dev/smol` | 本地 microVM 中的 Chromium，每个 attempt 从热浏览器 copy-on-write 分支 | `web({ browser: smol() })`；需 smol 引擎（Apple Silicon 或 KVM Linux） |
| `@e2e-dev/eas` | EAS Simulators 云托管 iOS 模拟器/Android 模拟器（免本地 Xcode/SDK） | `mobile({ device: easSimulators() })`，需 `EXPO_TOKEN` |
| `@e2e-dev/github` | GitHub Actions reporter：单条 PR 评论 + job summary | `reporters: ['list', github()]` |

## 7. 典型工作流

### 7.1 日常开发

```bash
npx e2e run                          # 全量（agent 步骤大多命中缓存，无模型调用）
npx e2e run --no-cache --headed      # 强制模型驱动 + 可视化调试某个测试
npx e2e run --last-failed            # 修完只重跑失败项
npx e2e run --debug                  # 看每阶段耗时与 agent 步骤成本
```

### 7.2 调试 agent 行为

```bash
npx e2e run tests/agent.e2e.ts --ai-trace --no-cache
npx unbox-ai runs .e2e/ai-trace.json           # 每个 agent 步骤一行
npx unbox-ai summary .e2e/ai-trace.json --run 3 # 单步：轮次、token、缓存
npx unbox-ai tools .e2e/ai-trace.json --run 3   # 模型调了哪些工具
```

失败时先看 `.e2e/results/<test>/trace.md`（每测试的 trace 页）与报告里的截图/视频。

### 7.3 CI（GitHub Actions）

- 官方提供 GitHub Actions / EAS Workflows / Bitrise / Codemagic 集成文档。
- CI 下默认 `workers=1`、`retries=1`、缓存只读；把 `.e2e/cache/` 提交进仓库可让 agent 套件以确定性速度和成本门禁 PR（录制过期时 `--strict-cache` 报 `REPLAY_STALE`）。
- `--shard` 分片并行；`@e2e-dev/github` 把结果聚合成一条 PR 评论。

### 7.4 给编码代理使用

```bash
npx e2e guide            # 打印完整 skill
npx e2e guide cache      # 打印某个主题
npx skills add tester-army/e2e   # 安装 e2e 技能
```

`e2e init` 会自动把 skill 装进 `.claude/skills/` 并注册 MCP；此后直接对 Claude Code / Codex / Cursor 说"给结账流程加个测试"即可。发布包内自带全部文档（`node_modules/e2e/docs`），代理可离线阅读。

## 9. 常见问题

**Q: 不配模型能用吗？**
A: 能。不含 agent 步骤的测试（纯 locator + expect）完全不需要模型；`e2e init` 选 "None" 即可。首次使用 `agent.act` 前再补配模型。

**Q: 回放缓存什么时候失效？**
A: 缓存条目（`.e2e/cache/` 的 `trace-1` 记录）按步骤参数摘要、目标 app identity、环境等键控。app 变化导致录制不再可回放时默认回退到模型；`--strict-cache` 则直接失败，适合 CI 门禁。想强制走模型用 `--no-cache`。

**Q: Windows 上怎么用？**
A: 官方 quickstart 明确"**On Windows, run inside WSL**"。Web 测试理论上依赖的 Playwright 支持 Windows，但项目 CI 无 Windows runner、文档不承诺原生支持，建议 WSL。详见《Windows兼容性分析.md》。

**Q: 怎么降低 token 成本？**
A: ① 确定性操作全部用 locator 而非 agent；② 让 agent 步骤命中回放缓存（配 `unique()`、稳定 `app.identity`）；③ 用 `@e2e-dev/decision` 决策模型执行器替代对话式 agent；④ 判定模型（judge）可单独配更小的模型；⑤ `--debug` / `--ai-trace` 观察每步开销。

**Q: 密码等敏感信息会发给模型吗？**
A: 不会。secret 由 runner 授权填充（`typeSecret` 只接受步骤 params 声明的句柄），模型输入是脱敏后的语义树；一旦填过 secret，该 attempt 的截图保持"像素污染"不再发送。会话按 run 加密（AES-256-GCM）、结束即删。

**Q: API 测试（非 UI）能做吗？**
A: 官方文档有 api-testing 页（通过 `browser` fixture 的网络能力与请求路由）；核心定位仍是 UI 驱动测试。

**Q: 怎么从 Playwright/Cypress/Selenium/Detox/Maestro 迁移？**
A: docs/migrate/ 下每个工具都有一页迁移指南。
